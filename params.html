預覽區

嵌入 PokéStroll 前後會用到的一切都在這: 參數總表(網址掛 query string 客製行為, 不用改任何程式或設定檔)、一鍵嵌入碼(調好的參數直接變成可貼的片段)、postMessage 遙控, 用下方頁籤切換。 旁邊那塊是即時預覽區——每個參數、每道食譜、每道遙控指令都能一鍵丟進去看效果。 位置用標題旁的按鈕挑: 上／下是一條橫軌(跟嵌入頁尾的實際樣子一致), 左／右是文件、預覽對半分(滿高畫面, 測飛行軌跡用), 選無就整塊關掉。

參數總表

共 個參數。點參數名稱直接複製; 點列尾的 + 把該參數（帶示範值）加進預覽區。用下方子頁籤依分類篩選(遙控類參數也在這)。

參數型別允許範圍預設說明

預設值以部署當下的 config.js 為準; 此頁與 PARAMS.md、程式內的參數白名單由 CI 自動檢查同步。

容錯規則

亂帶參數不會弄壞頁面, 規則如下(都會在瀏覽器 console 留下警告):

  • 不在表上的參數: 直接無視。
  • 非數字或超出允許範圍: 忽略該參數, 使用預設值。
  • minId > maxId 或 lookTimeMin > lookTimeMax: 自動對調。
  • boundsMin >= boundsMax: 整組退回預設 0.1 ~ 0.9。
  • count 超過可抽選的編號數量: 自動夾到 maxId - minId + 1(避免抽選卡死)。
  • ids 內的非法編號: 逐一剔除, 全部非法才退回隨機抽選。
  • team 內不認識的屬性名: 逐一剔除, 全部都不認識才當作沒帶(回到不限屬性)。
  • team 可抽的名單比 count 短: count 夾到名單長度; 名單完全是空的(該編號範圍內沒有那個屬性)則退回隨機抽選。

一鍵嵌入碼

四種上線方式各一張卡, 全部吃預覽區當下的參數—— 去調校台拉一拉、或直接改預覽區上方的網址列, 下面每一段程式碼都會立刻跟著變。 複製下來就是你剛才看到的那個樣子, 不用自己拼網址、不用自己記 URL 編碼。

🎛️ 目前帶的參數 (沒有帶參數, 用 config.js 的預設值)

要改就去 🎚️ 調校台頁籤(一參數一根拉桿), 或直接編輯預覽區上方的網址列。

① 一般網頁: iframe 疊在頁尾

背景透明、pointer-events:none 讓點擊穿透, 不會擋到頁面上的任何按鈕; 參數直接掛在網址後面, 各專案互不影響。 想讓訪客戳、抓寶可夢就拿掉 pointer-events:none, 但整個 iframe 矩形都會開始攔截點擊, 請自行取捨。 color-scheme:light 是透明背景的保險: iframe 內外的配色方案不一致時, 瀏覽器會在後面墊不透明底——你的頁面若宣告過 color-scheme: dark, 這一句能讓內外對齊。

② OBS: 瀏覽器來源

來源 → 新增 → 瀏覽器 → 網址貼上面那一串 → 寬高設成跟畫布一樣(例如 1920 × 1080) → 擺到圖層最上面。背景本來就是透明的, 不用調。 也可以改勾「本機檔案」選 pokemon_footer_widget.html, 那就改設定 config.js (改完在來源的屬性視窗按「重新整理目前頁面的快取」)。 OBS 沒有滑鼠, 所以想讓名字上鏡要明講 nametag=on——預設的 hover 在這裡永遠不會觸發。

③ 要即時遙控: iframe + postMessage

指令表與回執欄位見 📡 postMessage 遙控頁籤, 那裡還能直接按按鈕試打。

④ 要接外部訊息來源: 指令橋接 bridge.html

把你的來源網址填進上面那格就好。widget 的參數會自動編碼進 q= 一起帶走(bridge 再轉交給裡面的 widget), 不用自己算 URL 編碼。 參數表與訊息格式見下方📡 postMessage 遙控頁籤的「指令橋接」一節。

⑤ 嵌這份說明文件(團隊 wiki / 開發者後台適用) <iframe src="https://rd7-ai-gw-02.i17game.net/poke-stroll/params.html" title="PokéStroll 參數文件" style="width:100%; height:80vh; min-height:600px; border:none;" loading="lazy"></iframe>

跟嵌 widget 相反: 文件頁要互動, 不要加 pointer-events:none; 高度給足(建議 80vh 且 ≥ 600px), 搜尋、試玩按鈕和預覽區才施展得開。

postMessage 遙控

URL 參數是「載入時」的客製; postMessage 是執行中的遙控—— 父頁面隨時能隔著 iframe 疆界下指令(讓使用者從你的介面即時召喚寶可夢, 就是靠這個)。 它是瀏覽器原生的跨視窗通道, 不走網路、不受 CORS 限制, 跨網域 iframe 直接可用。 總開關與節流見參數表的 remote / remoteRateLimit。

🕹️ 現場試玩——指令直接打進預覽區
(按上面的按鈕, widget 的回執會即時顯示在這裡)

burst 要場上有色違才有效果(回執的 count 會告訴你作用到幾隻)——先按食譜「全員色違遊行」再回來玩; feed 掉的果實數量隨機, 上限是「有空的」常駐成員數(一隻只追一顆); 信使鳥空投時大家都在忙的話, 果實會被整顆叼走不落地; roster 的回執就是目前陣容清單, 直接看下面的回執列。

快速開始(嵌入方網頁) <iframe id="poke" src="https://rd7-ai-gw-02.i17game.net/poke-stroll/" style="position:fixed; bottom:0; left:0; width:100%; height:200px; border:none; pointer-events:none; color-scheme:light;"></iframe> <script> const poke = document.getElementById('poke'); function pokeCmd(cmd, extra = {}) { poke.contentWindow.postMessage({ ns: 'poke-stroll', cmd, ...extra }, '*'); } pokeCmd('spawn', { id: 143 }); // 例: 客串一隻卡比獸高速飛過 // 回執(除錯與確認送達用) window.addEventListener('message', e => { if (e.data?.ns === 'poke-stroll' && e.data.re) console.log(e.data); }); </script>
指令參數效果
spawn id(選填, 1 ~ 1025)
delivery(選填, true)		 客串一隻從畫面外高速橫越。帶 id 指定誰路過(不限飛行系, 遙控的卡比獸也能飛); 不帶就照常抽飛行池(含傳說機率那一層)。帶 delivery: true 改派信使鳥空投: 叼著果實橫越、半路鬆爪掉下一顆(大家都在忙就整顆叼走; berry=off 回 berry is off)。色違照全頁 shinyChance 擲骰
poke id(選填) 開心跳一下 + 冒愛心(跟滑鼠右鍵點本體同一種互動)。帶 id 只戳該圖鑑編號的成員, 不帶就全員; 正被滑鼠抓在手上的戳不動, 回執的 count 也不算牠
burst — 場上所有色違立刻重播星星特效(重播排程會重排, 不會越放越密); 沒有色違就是 count: 0
join id(選填, 1 ~ 1025) 加入一隻常駐成員(會留下來散步, 不是路過的客串)。帶 id 指定誰入隊, 不帶就照 minId / maxId 隨機抽; 回執的 id 告訴你誰來了。隊伍上限與 count 參數同一個天花板(50), 滿了回 party is full
leave id(選填) 送走一隻常駐成員。帶 id 指定送誰(同編號多隻就送最晚入隊的), 不帶就隨機挑; 回執的 id 告訴你誰走了。最後一隻不送(回 last one standing); 正在追的果實會一併收走, 不留孤兒果實; 正被滑鼠抓在手上的會先自動鬆手
feed count(選填, ≥ 1) 從天上隨機位置降下果實, 掉法與點擊空白處丟果實同一套(最近且有空的成員冒驚嘆號跑去吃)。帶 count 指定顆數, 不帶就隨機; 上限都是「有空的常駐成員數」(一隻只追一顆; 被滑鼠抓在手上的也不算有空), 回執的 count 是實際掉了幾顆。大家都在忙回 everyone is busy
roster — 查詢目前常駐陣容, 不動畫面。回執帶 count(總數)與 roster 陣列, 每隻是 { id, name, shiny, size }(圖鑑編號 / 繁體中文名 / 是否色違 / 體型倍率 0.6 小、0.8 中、1 大)。要做陣容面板、投票名單之類的整合, 資料從這裡拿
  • 訊息格式: { ns: 'poke-stroll', cmd: '…', …參數 }。沒帶 ns 的訊息一律無視——父頁面常有別的 iframe 在互傳訊息, 不是寄給我們的信不拆。
  • 回執: 每道指令都回 { ns, re, ok, count?, id?, roster?, reason? } 給發送方; reason 可能是 unknown cmd / id must be 1~1025 / id not found / cameo pools not loaded / page hidden(背景分頁不演視覺效果) / rate limited / party is full / last one standing / berry is off / everyone is busy / count must be >= 1。
  • 節流: 每秒最多 remoteRateLimit(預設 10)道, 超額整道丟棄——高頻灌指令也拖不垮渲染。
  • 總開關: ?remote=off 後完全靜默(連回執都不給, 像沒這功能)。
  • 刻意不驗 origin: 指令全是無害的視覺效果、無機密無狀態, 最壞情況是有人在他自己的頁面上讓皮卡丘跳舞。要鎖就直接 remote=off。

指令橋接(bridge.html)

後台服務、bot 等外部程式碰不到 postMessage(不同行程、沒有共同的瀏覽器語境)。 同捆的 bridge.html 就是那道門: 對外連一個訊息來源、把收到的東西翻成遙控指令、對內丟進 iframe 裡的 widget。 不用寫程式, 帶網址參數就能用; widget 本體完全不用改, 也不知道指令從哪來。

開一頁就開始運作(擇一) bridge.html?ws=wss://your-service.example/stream bridge.html?poll=https://your-service.example/latest.json&pollInterval=3000
↗ 開啟 bridge.html

直接開(不帶來源)會顯示用法說明, 不是一片空白。

來源送來的東西解讀
{"cmd":"feed","count":2} 直接照做。欄位名與上面的指令表一致, 不必帶 ns
{"sender":"svc-a","text":"…"} 從 text 挑指令; sender(或 user)用來算冷卻
純文字一行 從整行挑指令。只認「前綴 + 已知指令」這個組合, 所以整行包在別的協定裡(前面有時戳、路由前綴之類)也挑得出來, 又不會把隨便一個驚嘆號當成指令

文字模式認得的指令詞(前綴可改):

指令詞等於
!spawn / !spawn 143spawn 客串一隻橫越
!dropspawn + delivery 信使鳥空投果實
!feed / !feed 3feed 天降果實(帶顆數)
!poke / !poke 25poke 戳一下
!join 133 / !leavejoin / leave 加入、送走常駐成員
!burst / !rosterburst / roster

橋接頁自己的參數(跟 widget 的參數分開, 寫在 bridge.html? 後面):

參數預設說明
ws— WebSocket 來源網址。斷線自動重連, 退避 1→2→4…秒, 最多 30 秒
poll— 改用輪詢: 定期 GET 這個網址, 回傳 JSON 物件或陣列。與 ws 擇一
pollInterval3000 輪詢間隔 ms(500 ~ 600000)
hello— 連上後要先送出的行, | 分隔——有些文字協定得先報到才會開始送資料
prefix! 文字指令的前綴
allow全部 指令白名單, 逗號分隔(如 allow=feed,poke)。看不懂的名稱會被剔除
cooldown3000 同一個 sender 的冷卻 ms。widget 端的節流是「全場」額度, 這一層讓額度不會被單一來源一口氣吃光。0 = 不擋
q— 轉交給 widget 的參數, 例 q=theme%3Dgrass%26count%3D6(記得 URL 編碼: = 是 %3D、& 是 %26)
statuson 左上角的狀態列(連上了沒、送出幾道、最近一道)。off 收起來
  • 保活: 來源送 PING 會自動回 PONG(許多文字協定的慣例)。
  • 除錯: 回執若是 ok:false 會印在 console——不必猜是「沒送到」還是「送到了但被拒絕」。
  • 兩層防護: 橋接頁擋同來源的高頻, widget 端另有全場每秒節流, 兩層各管各的。
進階: 自己寫 wrapper——來源協定太特別、或想在轉譯這層加自己的商業邏輯時, 照抄這個骨架 <!-- wrapper.html: OBS 或任何頁面載入這一頁(widget 本體完全不用改) --> <iframe id="poke" src="./pokemon_footer_widget.html" style="position:fixed; inset:0; width:100%; height:100%; border:none;"></iframe> <script> const poke = document.getElementById('poke'); // 對外連你自己的服務: 後台推播、事件匯流排…任何 WebSocket 來源都行 const ws = new WebSocket('wss://your-service.example/events'); ws.onmessage = ev => { // 服務端推 {"cmd":"spawn","id":143} 之類的 JSON 事件, 轉譯成 postMessage; // wrapper 這層先過白名單, 不認識的指令不轉發 const m = JSON.parse(ev.data); if (['spawn', 'join', 'leave', 'feed', 'poke', 'burst', 'roster'].includes(m.cmd)) { poke.contentWindow.postMessage({ ns: 'poke-stroll', ...m }, '*'); } }; </script>

widget 端已內建每秒節流; 想更嚴(單一使用者冷卻、權限限定)就在 wrapper 這層做——事件來源相關的邏輯全關在 wrapper 裡, widget 完全不用知道指令從哪來。
